## 0. 一句話定義這個視窗負責什麼

把「美甲美睫店的內容生產 SOP」→ 標準化 → 自動化 → 最終做成**賣給美容大類同行的 SaaS 訂閱產品**。

---

## 1. 終極願景（使用者親口確認）

| 項目 | 內容 |
|------|------|
| 產品形態 | SaaS 多租戶，月費訂閱 |
| 目標客群 | 美容大類：美甲美睫 / 美體 / 美髮 / 紋繡 / SPA |
| 核心價值 | 幫店家把內容生產（拍照→美化→文案→多平台發布）工時砍掉一半以上 |
| 商業模式 | 訂閱制（別店自己註冊、上傳照片、自動產出並發布內容） |

---

## 2. 教練紅線（不可跳過，違反請看這條）

🚫 **市場尚未驗證。** 使用者自承目標買家需求「只是我覺得有需求」，未實際問過任何同行。

→ 因此**階段 0（市場驗證）是強制 gate**。階段 0 沒過，不准進入階段 2 以後的商品化工程。
→ 失敗模式：先造船再找乘客 = 燒大量工時做出沒人付費的系統。
→ 這條紅線寫進章程，就是要在你日後想跳過驗證直接衝開發時擋下你。

## 3. 分階段路線圖（每階段獨立 done-condition）

### 階段 0 — 市場驗證 gate（最該先做，工時最低）
- **動作**：完成階段 1 自用 MVP 後，拿真實成果（工時數據 + 產出樣本）去問 **5 個美容業同行**：願不願意每月付費用這套？願付多少？
- **done-condition**：至少 3/5 表達明確付費意願 + 說得出可接受月費區間
- **概估時程**：訪談 1-2 週（不需寫程式）
- **沒過怎麼辦**：停在階段 1 自用，不商品化

### 階段 1 — 自用 MVP（沉沒成本，本來就該做）
- **動作**：自己店的內容生產流程做出可用的半自動工具（已進行中）
- **done-condition**：自己店內容生產工時從 2-3hr/天 → 1hr 內，且有前後工時實測數據
- **概估時程**：3-5 個工作天（視素材到位速度）
- **目前進度**：見第 4 節

### 階段 2 — 可複製工具包（階段 0 通過才啟動）
- **動作**：把 SOP + 半自動工具打包成「別店照著用」的形態（文件 + 工具，尚非多租戶系統）
- **done-condition**：1 家外部店實際試用，能在無你協助下產出可發布內容
- **概估時程**：1-2 週

### 階段 3 — SaaS 多租戶（有付費客戶才啟動）
- **動作**：多租戶註冊、上傳、自動套版、串 Meta/LINE/Google 商家 API 自動發布、訂閱金流
- **done-condition**：≥1 個付費租戶穩定使用一個月
- **概估時程**：大型工程，待階段 0-2 完成後重新估
- **抽象化要點**：客群是美容大類 → 模板/文案需做「行業參數化」（美甲/美髮/SPA 各自的款式詞彙、流程詞彙），不能寫死美睫
